## 1. B｜多代备份与回滚（重点）

| # | 操作 | 预期结果 |
|---|---|---|
| 1.1 | 客户端登录 **A**，记下当前客户端登录的是谁 | — |
| 1.2 | CheckinBox 里对 **B** 点「切换客户端账号」 | 切换成功，客户端变成 B |
| 1.3 | 跑 `CheckinBox.exe --list-client-backups minimax` | 列出 **1 代**，能看到操作id、时间、原因 `switch`、**被备份的原始文件路径** |
| 1.4 | 再切回 **A** | 客户端变成 A |
| 1.5 | 再跑一次 `--list-client-backups minimax` | 列出 **2 代**（不是 1 代）—— 旧行为这里只会永远是 1 代 |
| 1.6 | 打开备份目录，第 1 代里的 `auth.json` | 内容 = **1.2 切换之前**的现场（即 A 的登录态），不是 B 的 |
| 1.7 | 第 1 代目录里应同时有 `auth.json` 与 `auth-state.json` | 两个文件都在（成组）；缺一半回滚会让客户端弹登录框 |
| 1.8 | 切到 **B**（第 3 次） | 客户端变成 B |
| 1.9 | 回滚到**第 2 代**：`CheckinBox.exe --restore-client-backup minimax <第2代操作id>` | 提示「已回滚…（回滚前的现场已另存一代）」 |
| 1.10 | 重启客户端，看登录的是谁 | 应该是**第 2 代**记录的账号（B→A 那次切换之后的 A） |
| 1.11 | 再跑 `--list-client-backups minimax` | 回滚前的现场也存成了一代（`pre-restore`），所以代数为 4 |

**判定点**：1.5 / 1.6 / 1.10。旧实现下 1.5 永远只有 1 代、1.10 也回不去。

**顺带看一眼**：切换后 `auth.json` 里 `generation` 应比切换前 **大**（= 旧 generation + 1），
`auth-state.json` 的 `generation` 与之一致 —— 不一致的话客户端会弹登录框。

| # | 操作 | 预期结果 |

**判定点**：2.3 与 2.5。

## 3. A｜客户端在跑时，401 不再自动刷新（不顶掉客户端）

| # | 操作 | 预期结果 |
|---|---|---|
| 3.1 | 客户端**保持运行**并登录账号 **A** | — |
| 3.2 | 在 CheckinBox 里对 **A** 手动刷新配额 / 点签到 | 若遇到 401，看错误文案 |
| 3.3 | 错误文案 | 应包含「**没有自动刷新**」并说明原因（客户端当前登录的就是这个账号 / 无法确认客户端是否在运行），**而不是**旧版的「自动刷新后仍被拒绝」 |
| 3.4 | 关键：看客户端 | **没有掉线**（仍显示已登录，不会退回登录页） |
| 3.5 | 退出 MiniMax Code 客户端，再手动刷新 A | 此时应能**自动刷新成功**（确认没在跑 → 允许自刷新） |
| 3.6 | 重新打开客户端 | 登录态正常，账号仍是 A |

**判定点**：3.4（不掉线）与 3.5（关掉客户端后能自动刷新）。

> 这一条对应 2026-11-11 在上游 cockpit-tools 上复现的掉线：上游刷新时会抄客户端的
> refresh token 再用它刷新，RT 一轮换，客户端内存里那份就作废 → 下次续期
> `invalid_grant` → `delete_credentials` → 掉线。**两个账号时掉的是客户端当前登录的那个。**
